# 小熊农场：离线模拟与存档技术说明

> 对应模块：`:game:farm`（小熊农场）
> 核心文件：`FarmSimulator.kt`（规则引擎：tick/种植/照料/收获/买卖/周目）、`FarmCrops.kt`（`CropDef`/128 作物表/`FarmPlotState`/`FarmSave`/解锁与概率公式）、`FarmState.kt`（`BearFarm` UI 状态壳、回档纯逻辑、音效映射）、`BearFarmScreen.kt`（帧循环/自动存档/返回键）、`FarmSky.kt`（昼夜与天气氛围）、`FarmField.kt`（田地格子/需求气泡/工具栏）、`FarmCatalogDialogs.kt`/`FarmShopDialog.kt`/`FarmInventoryDialog.kt`（图鉴/商店/背包）、`FarmCropArt.kt`（插画映射）；`FarmWeather` 与场景码映射复用 `:game:common` 的 `FarmWeatherCommon.kt`
> 摘要：本文说明一款挂机经营小游戏如何把「时间推进」与「渲染帧」解耦：`tick` 以 200ms 为最小步进、离线按 1 分钟切片追赶最多 8 小时，用「至少发生一次」公式驱动杂草/害虫/枯萎；128 种作物按类别定义喜好天气与生长/售价加成；存档 JSON 从 schema 1 迁移到 2 并回填图鉴，5 秒自动落盘加退出兜底；文末如实记录英文界面仍显示中文作物名的 i18n 缺口。

## 1. 分层与数据模型

| 层 | 文件 | 职责 |
|----|------|------|
| 纯数据 | `FarmCrops.kt` | `FarmPlotState`（单格）、`FarmSave`（持久化模型）、`CropDef`（作物定义） |
| 规则引擎 | `FarmSimulator.kt` | `FarmState` 全量状态、`tick` 推进、各类经营动作 |
| UI 状态壳 | `FarmState.kt` | `BearFarm` 持有 Compose 状态，动作后 `syncFromState`，把 `FarmEffect` 翻译成 toast/飘字/解锁卡/音效 |
| 界面 | `BearFarmScreen.kt` 等 UI 文件 | 帧循环、自动存档、弹窗、天空与田地渲染 |

`FarmState.plots` 固定 `FARM_PLOT_COUNT = FARM_COLS * FARM_ROWS = 5 × 4 = 20` 格。`FarmPlotState` 由 `cropId`、`stage`（0 空/1 种子/2 发芽/3 成长/4 成熟/5 枯萎）、`stageProgress`（0..1）、`moisture`（0..1，低于 0.25 阻断生长、低于 0.08 参与枯萎判定）、`weed`/`bug`（存在即阻断生长）、`lastTickMs`（离线追赶锚点）组成。`FarmState` 另有 `coins`、`unlocked`、`harvestedTotal`、`harvestCounts`（跨周目图鉴）、`inventory`、`completedSeasons`、`lifetimeHarvests`、`seasonCollected`，派生 `currentSeason`/`collectedCount`/`seasonCollectedCount`/`seasonGoal`/`seasonReady`/`allCollected`。

## 2. 时间模型：200ms 步进与离线追赶

推进参数写死在 `FarmSimulator.tick(state, now, weather, random)` 内：

| 常量 | 值 | 语义 |
|------|----|------|
| `minStepMs` | 200 | 最小推进步进，不足不推进（下次累计） |
| `maxCatchUp` | 8h | 单次调用最多追赶 8 小时，超出部分丢弃 |
| `sliceMs` | 60_000 | 追赶切片，整分钟用预计算的精确概率 |

```kotlin
val needsWork = state.plots.any { p ->
    val last = p.lastTickMs
    last <= 0L || last > now || now - last >= minStepMs
}
if (!needsWork) return
```

单格逻辑：`lastTickMs <= 0` 用 `now` 初始化；`elapsed < 0` 视为时钟回拨，把 `lastTickMs` 收敛到 `now` 并记 `elapsed = 0`（否则农场会冻结到墙钟追平）；`elapsed` 先夹到 8h，再按 `min(remaining, 60s)` 切片循环。整分钟切片用 `farmChanceAtLeastOnce` 的精确概率，尾切片用 `weedChancePerHour * hours` 的线性近似（注释说明误差可忽略）；循环末尾 `plot.lastTickMs = now`。整段 `elapsed` 不足 200ms 时直接返回、`lastTickMs` 不动，余量留到下一次累计；长追赶切完后不足 200ms 的零头会被末尾写回吞掉，量级可忽略。

每次切片按顺序结算：`moisture += (-dryPerHour + rainPerHour) * hours`（夹 0..1）；`stage in 1..4` 时按 `weedP`/`bugP` 概率置 `weed`/`bug`（已长不重复判定）；`stage in 1..4 && moisture < 0.08` 且命中 `wiltP` 时置 `stage = 5`、`stageProgress = 0`；最后调 `advanceGrowth`。

```kotlin
// advanceGrowth：离线模拟与金肥料共用
if (plot.stage !in 1..3) return
if (plot.weed || plot.bug || plot.moisture < 0.25f) return
val mul = fx.growthMul * (0.7f + 0.3f * plot.moisture) * seasonMul * prefMul
plot.stageProgress += (hours / needH) * mul
```

`needH` 是 `CropDef.stageHours` 对应阶段时长（下限 0.2h）；进度溢出会连升多级，到 `stage >= 4` 时夹为成熟且 `stageProgress = 1`。枯萎概率按「每天 25%」的极宽松口径（`0.25 / 24` 每小时）折算，缺一两天水几乎不枯，连续干旱数天才明显。`farmChanceAtLeastOnce(p, hours) = 1 - (1 - p) ^ hours`（夹 0..1），避免长离线后 `p * hours > 1` 导致「必出草/必枯萎」；`FarmCatchUpTest` 固定断言 8 小时雨天杂草概率小于 1 且大于 0.6。

## 3. 作物与天气

### 3.1 `CropDef` 与 128 种作物

`CropDef` 字段：`id`/`nameZh`/`emoji`、`seedCost`/`sellPrice`、`stageHours: FloatArray`（种子→发芽、发芽→成长、成长→成熟三段时长，`totalHours` 求和）、`color`/`leafColor`（当前仅存于数据模型，渲染层未读取）、`category`（默认「蔬菜」）、`description`（取自 `FARM_CROP_DESCRIPTIONS`）。`FARM_CROPS` 共 128 项（`farmCrops_hasExactly128Entries` 守门），列表顺序即收获解锁顺序，花卉靠前方便早解锁；类别数量为蔬菜 25、花卉 47、谷物 8、水果 24、香草 11、菇菌 3、其他 10。列表末尾用 `CropDef.scaled(costMul, hourMul)` 加价加时，售价与种子价同比例缩放以保持利润率：

| 解锁序号 index | `costMul` | `hourMul` |
|----------------|-----------|-----------|
| `>= 118` | 2.2 | 1.8 |
| `>= 104` | 1.7 | 1.5 |
| `>= 90` | 1.4 | 1.3 |
| 其余 | 1.0 | 1.0 |

喜好天气只按 `category` 推导（`preferredWeatherOf`），不逐株配置；命中时生长加成 `CROP_PREFERRED_GROWTH_BONUS = 0.20`、售价加成 `CROP_PREFERRED_SELL_BONUS = 0.25`：

| 类别 | 喜好天气 | 生长 | 售价 |
|------|----------|------|------|
| 谷物、香草 | 雨天 | +20% | +25% |
| 水果、蔬菜 | 晴天 | +20% | +25% |
| 花卉 | 多云 | +20% | +25% |
| 菇菌 | 雾 | +20% | +25% |
| 其他 | 无 | 无 | 无 |

售价加成必须高于通用晴天加成（1.15），否则「喜晴」作物在晴天只会吃到通用加成，喜好形同虚设（`FarmBalanceTest.sellPrice_preferredWeatherAddsBonus` 专门守住这一点）。

### 3.2 天气效果表

`farmWeatherEffect(weather)` 是全部数值的来源（`FarmCrops.kt`）：

| 天气 | `growthMul` | `dryPerHour` | `rainPerHour` | `weedChancePerHour` | `bugChancePerHour` |
|------|-------------|--------------|---------------|---------------------|--------------------|
| `SUNNY` | 1.25 | 0.22 | 0 | 0.04 | 0.05 |
| `CLOUDY` | 1.0 | 0.12 | 0 | 0.06 | 0.06 |
| `RAINY` | 1.1 | 0.02 | 0.35 | 0.14 | 0.04 |
| `STORMY` | 0.9 | 0.03 | 0.45 | 0.10 | 0.18 |
| `SNOWY` | 0.45 | 0.04 | 0.05 | 0.02 | 0.02 |
| `FOGGY` | 0.75 | 0.08 | 0.08 | 0.08 | 0.07 |

场景码到 `FarmWeather` 的映射在 `:game:common` 的 `farmWeatherFromScene(sceneCode, isDay)`：95..99 → `STORMY`（冰雹并入雷暴）、71..77/85/86 → `SNOWY`、45..48 → `FOGGY`、51..67/80..82 → `RAINY`、0/1 →（夜间 `CLOUDY`、白天 `SUNNY`）、2/3 → `CLOUDY`；`sceneCode` 为空时夜间 `CLOUDY`、白天 `SUNNY`，其余未识别码 `CLOUDY`。农场不做降水强度细分，冻雨与普通雨同为 `RAINY`。

## 4. 经济与进度

### 4.1 金币、解锁与商店

初始 `coins = 80`、解锁 `radish/cabbage/wheat/tomato` 四种。收获不解锁金币，只有卖出进账；收获本身按 `harvestedTotal` 推进下一种作物的解锁（`unlockByProgress`），门槛曲线「前期快、后期慢」：

| 已解锁数量 n | `farmUnlockNeed(n)` |
|--------------|---------------------|
| `n >= 128` | `Int.MAX_VALUE`（不再解锁） |
| `n < 8` | `(n - 3).coerceAtLeast(1) * 2` |
| `n < 20` | `10 + (n - 8) * 3` |
| `n < 40` | `46 + (n - 20) * 4` |
| `n < 60` | `126 + (n - 40) * 5` |
| 其余 | `226 + (n - 60) * 6` |

商店 `buyUnlock` 直接购买解锁，价格固定 `farmUnlockPrice(crop) = crop.seedCost * 5`（`farmUnlockPrice_matchesEveryCropSeedCost` 逐项校验）。一次性道具 `FARM_SHOP_ITEMS`：

| 道具 | 价格常量 | 效果 |
|------|----------|------|
| 小雨壶 `rainAll` | `RAIN_CAN_COST = 15` | 全田 `stage in 1..4` 且未满水的格子 `moisture += 0.45` |
| 除虫喷雾 `bugAll` | `BUG_SPRAY_COST = 20` | 清除全田 `bug` |
| 除草剂 `weedAll` | `WEED_KILLER_COST = 20` | 清除全田 `weed` |
| 金肥料 `fertilize` | `FERTILIZE_COST = 25` | 对 `stage in 1..3`、无草无虫、`moisture >= 0.25` 的格子推进 `FERTILIZE_HOURS = 2f` 小时 |

### 4.2 售价与背包

`farmSellBonus` 给出通用天气加成：晴天 1.15、雨天 1.05、其余 1.0。单株售价取通用与喜好的**较大值**（不是相乘），口径与背包顶部 `bestSellBonusOf(inventory.keys, weather)` 一致，避免「顶部无加成、卡片却有喜好价」的矛盾：

```kotlin
fun sellPriceOf(crop: CropDef, weather: FarmWeather): Int {
    val weatherBonus = farmSellBonus(weather)
    val preferredBonus = if (crop.prefers(weather)) 1f + CROP_PREFERRED_SELL_BONUS else 1f
    return (crop.sellPrice * maxOf(weatherBonus, preferredBonus)).roundToInt()
}
```

卖出支持单种清空（`sellAll`）与一键全卖（`sellAllInventory`）。每次收获会把作物写入 `inventory`、累加 `harvestCounts` 与本季 `seasonCollected`、`harvestedTotal`/`lifetimeHarvests` 各加一。

### 4.3 周目（season）与重置

| 项 | 公式/行为 |
|----|-----------|
| 当前季 | `currentSeason = completedSeasons + 1` |
| 开季门槛 | `seasonGoal = (12 + completedSeasons * 4).coerceAtMost(40)` |
| 永久生长加成 | `seasonGrowthPercent = 5% × completedSeasons`，封顶 `MAX_SEASON_BONUS_PERCENT = 25` |
| `startNewSeason` | 重置 `coins = 80`、田地（`lastTickMs = now`）、`unlocked` 初四种、`harvestedTotal = 0`、`seasonCollected` 清空；保留背包、图鉴、`lifetimeHarvests`；`completedSeasons++` |

`allCollected` 表示「本季集齐全部 128 种」，是开季门槛之外的可选成就；`collectedCount`（`harvestCounts.size`）是跨周目图鉴收藏数，两者在图鉴里分开显示。项目没有独立的成就系统，`allCollected`、图鉴计数与周目加成是当前全部进度型奖励。

### 4.4 一键照料与反馈

`careAll` 按固定优先级逐格处理：害虫 > 杂草 > 成熟收获 > 缺水（`stage in 1..4 && moisture < 0.35f`）> 枯萎清理；收尾汇总「收/浇/除/杀/清」计数。单格 `applyCare` 多一条空地为「请用播种工具」的提示。动作反馈统一走 `FarmEffect(toastRes, toastArgs, rewards, unlockCropIds)`，由 `BearFarm.applyEffect` 翻译：`rewards`（`FarmRewardSpec(plotIndex, label)`）变成按网格行列锚定的飘字 `FloatingRewardItem`；`unlockCropIds` 变成解锁弹卡（已有卡在显示时先入 `unlockQueue`，`dismissUnlockCard` 逐个弹出）；toast 带自增 id，同文案连点也会重启 2.5 秒自动清除。

## 5. 存档与迁移

存档是 `kotlinx.serialization` JSON，key 为 `"farm_save_v1"`，写在 `BearFarm` 的 `"bear_game"` SharedPreferences 中；`farmJson` 开启 `ignoreUnknownKeys` 与 `encodeDefaults`。`FarmSave` 共 10 个字段：`coins`、`plots`、`unlockedCropIds`、`harvestedTotal`、`harvestCounts`、`completedSeasons`、`lifetimeHarvests`、`schemaVersion`（默认 1）、`inventory`、`seasonCollected`；`FarmState.toSave()` 固定写 `schemaVersion = 2`。

### 5.1 1 → 2 迁移

旧档（1.x，无图鉴/周目字段）反序列化后相关字段走默认空值。`BearFarm.load` 把 `backfillUnlockedAsCollected = save.schemaVersion < 2 && save.unlockedCropIds.size > 4` 传给 `loadFarmFromSave`，`FarmState.fromSave` 据此回填：

```kotlin
val backfilledHarvestCounts =
    if (backfillUnlockedAsCollected) save.unlockedCropIds.toSet().associateWith { 1 }
    else save.harvestCounts
val oldSaveFullyCollected =
    save.schemaVersion < 2 && backfilledHarvestCounts.size >= FARM_CROPS.size
```

语义：老玩家的已解锁作物视为收集过，图鉴不从零开始；若旧档已覆盖全部 128 种，则本季收集也回填，可立即开新一季（`oldFullyCollectedSave_backfillsSeasonCollected`、`oldSaveUnlockedAllWithoutCounts_alsoBackfillsSeasonCollected`）；普通老档不会被错误加速（`oldPartiallyCollectedSave_doesNotFastForwardSeason`）。`fromSave` 还会把 `plots` 补齐/截断到 20 格、空 `unlocked` 回落到初始四种。

### 5.2 落盘时机与回档

每个格上操作（`onPlot`）与 `careAll`/道具/买卖/换季动作都会立即 `save()`；另有两条兜底：`GameRepeatingInterval(5_000L) { farm.save() }` 的 5 秒自动存档（与渲染帧解耦，见 `:game:common`），以及 `DisposableEffect.onDispose` 与关闭按钮的 `save()`。`save()` 与 `lastSaved` 相等时直接返回，不编码不写盘。

回档纯逻辑在 `FarmState.kt`：`loadFarmFromSave(save, currentSelectedSeedId, backfillUnlockedAsCollected)` 恢复纯数据状态，并返回 `FarmLoadedUi` —— toast/飘字/解锁卡/解锁队列一律清空，选中种子经 `seedIdAfterLoad` 归位（优先保留原选择，其次默认 `DEFAULT_SEED_ID = "radish"`，再取任一已解锁，最后仍回落默认值）。`BearFarm.load` 解码失败时 `runCatching` 静默返回，不覆盖当前状态。

## 6. 帧循环与渲染

```kotlin
GameFrameLoop(key = weather, maxDtSeconds = 0.05f, paused = { dialogOpen }) { dt, _ ->
    val needsHighFps = weather == FarmWeather.RAINY ||
        weather == FarmWeather.STORMY || weather == FarmWeather.SNOWY
    farm.tick(System.currentTimeMillis(), weather)
    animDt += dt
    if (needsHighFps || slowTick % 5 == 0) { farm.time += animDt; animDt = 0f }
    slowTick++
}
```

- `farm.tick` 每帧调用，但受 200ms 最小步进限制，实际约每 200ms 推进一步；
- 雨/雷暴/雪需要 60fps 粒子，动画时钟 `farm.time` 每帧推进；晴/多云/雾每 5 帧才写一次，Canvas 随之约 12fps 重绘，需求气泡与成熟 pulse 读取同一时钟；
- `dialogOpen` 覆盖商店/图鉴/背包/换季确认/解锁卡，弹窗期间帧循环不注册 vsync，恢复后由离线追赶补齐。

**农场没有暂停机制**：不设暂停菜单；返回键先按顺序关闭内容弹窗（换季确认与解锁卡亦然），否则 `save()` 后直接 `onExit()`。切后台由 `GameFrameLoop` 自动停推并重置帧时间（复用 `:game:common` 的生命周期感知逻辑）。

`FarmSky.kt` 的昼夜是独立氛围层：`farmSkyPhase(isDay)` 以本地钟点把夜晚再分为 `DUSK`（5–7 点、17–20 点）与 `NIGHT`，`BearFarmScreen` 每 5 分钟重算一次；白天沿用天气自带天空色，其余时段用 `farmSkyGradient` 的三色渐变。`drawFarmAtmosphere(weather, time, phase, reduceMotion)` 负责下雨/雷暴闪白、雪、晴天太阳光线、雾与飘云，`drawNightSky` 负责星空/月亮/暮光/萤火虫；`reduceMotion` 为真时跳过动态粒子与萤火虫，只保留静态太阳/月亮与天空。雾天叠色与 `FarmField` 的气泡/成熟 pulse 不受 `reduceMotion` 影响（现行为，见 §9）。`FarmCropArt` 负责插画映射：种子/枯萎共用，发芽/成长按类别与子形态（七组形态枚举）选图，成熟按作物 id 一对一映射、缺失时按类别兜底。

## 7. 音效与触感

`farmEffectCues(effect)` 是一次操作的 cue 纯映射：收获（带 rewards）与卖出进账 `COIN`，解锁 `STAR`，换季 `GOAL`，其余成功操作 `UI_CLICK`，失败 `BUMP`，无事发生静默；收获同时解锁时主音之后补一声 `STAR`（主音已是 `STAR` 不重复）。音效仅在 `applyEffect`（用户点击）触发，后台 tick/离线追赶不播。田地点击在 `onClick` 里播 `CLOCK_TICK` 触感，进入界面先 `GameAudio.preload(context)`。

## 9. 已知取舍与后续演进

| 取舍 | 现状与代价 |
|------|-----------|
| 8 小时追赶上限 | 长期不登录只结算 8 小时，避免一口气跳阶段/枯萎；代价是离线更久的部分被静默丢弃 |
| 尾切片线性近似 | 不足一分钟的步进用 `p * hours`，与整分钟的精确公式有微小误差；换取在线 tick 的常数开销 |
| 枯萎极宽松 | 每天 25% 且要求 `moisture < 0.08`，约 4–7 天连续干旱才明显；代价是挂机过夜几乎不会损失作物 |
| 喜好只按类别 | 不逐株配置，128 种作物只有 4 种偏好天气；代价是「芦荟喜晴」之类的直觉差异无法体现 |
| 收获不解锁金币 | 金币只能靠卖出或初始 80；新手容易先卡在种子钱不足，但也强化了「种—收—卖」循环 |
| 解锁弹卡排队 | 一次 `careAll` 可能解锁多张卡，用 `unlockQueue` 串行展示；代价是弹卡期间帧循环暂停（离线追赶补齐） |
| 不设暂停菜单 | 返回键只关弹窗或保存退出；挂机玩法下暂停语义弱，但玩家无法「开着界面暂停计时」 |
| `reduceMotion` 只作用于天空 | 田地需求气泡/成熟 pulse 仍随共享时钟滚动；后续可把 `LocalReduceMotion` 一并接入 `FarmField` |
| 没有独立成就系统 | `allCollected` 与图鉴计数承担进度展示；缺少可领奖的成就目标 |
| 英文界面仍显示中文作物名 | **已知 i18n 缺口**（见下） |

### 9.1 i18n 缺口说明（现状与工作量）

农场的 UI 骨架已经全量资源化：`values/strings.xml` 与 `values-en/strings.xml` 各 117 条，标题、工具、商店、图鉴、背包、toast 模板都有英文翻译。但**作物本身就是中文硬编码**：`FarmCrops.kt` 的 `CropDef.nameZh` 是「萝卜」「白菜」等中文字面量，`category` 是「蔬菜」等中文字面量；`FarmCropDescriptions.kt` 的 `FARM_CROP_DESCRIPTIONS` 是 128 条中文句子；种子条、图鉴、商店、背包、解锁弹卡与收获/出售 toast 都直接使用 `crop.nameZh`/`crop.category`/`crop.description`，因此英文界面下会出现「Harvested 1 萝卜」这类混排。这是被如实记录的已知缺口，而不是设计意图。

补齐工作量大致为：128 个名称 + 7 个类别 + 128 条描述在 `values`/`values-en` 各一份（约 526 条字符串），把 `CropDef` 的名称/类别/描述改成 `@StringRes` 或在读取处按 locale 解析，并新增「每个作物 id 都有中英文名称与描述」的回归测试；同时需要决定是否保留 `nameZh` 作为数据/日志字段以兼容存档与排序。保守估计是中大型改动，涉及 `FarmCrops.kt`、`FarmCropDescriptions.kt`、`FarmCropArt.kt`、三个弹窗与 `BearFarmScreen` 的展示层。

后续演进方向：追赶上限与枯萎率可配置化；商店/图鉴分页或搜索替代固定高度列表；把 `reduceMotion` 扩展到田地动效；把作物文案资源化并按 locale 输出（上节）。

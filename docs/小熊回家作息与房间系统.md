# 小熊回家：作息时间轴与房间系统技术说明

> 对应模块：`:game:home`（小熊回家）
> 核心文件：`BearHomeScreen.kt`（房间状态机、Hub 热区、各房间页与返回键）、`HomeRoutine.kt`（作息时间轴纯逻辑）、`HomeBalcony.kt`（天气联动阳台与粒子）、`HomeStreet.kt`（街上点位）、`HomeMealDex.kt`（三餐图鉴）、`HomeNarration.kt`（旁白映射）、`BearHomeEntry.kt`/`BearHomeEntryProvider.kt`（口令与 ServiceLoader 装配）；`FarmWeather`/`rainStrengthOf` 来自 `:game:common`，作息边界常量与 `SunPathBearMoment` 来自 `:core:designsystem`
> 摘要：本文说明一个「不以通关为目标」的休闲小屋：怎样用一张连续、无重叠的分钟段表表达小熊一整天的作息，并以凌晨 5:00 为日界让跨零点状态保持唯一；怎样用九值私有状态机组织 Hub 热区与房间导航，并把返回键语义收敛成「先出子层、再回客厅、最后退出」；阳台如何把真实天气映射到插画、文案与粒子且在没有特效时不注册帧循环；文末如实记录「房间交互基本为纯展示、没有解锁/事件进度」的现状。仓库中不存在 `HomeWeather.kt`，天气展示映射实际位于 `HomeBalcony.kt`。

## 1. 入口与分层

| 层 | 文件 | 职责 |
|----|------|------|
| 口令入口 | `BearHomeEntry.kt` | `password = EASTER_EGG_BEAR_HOME`（`#小熊回家`），把 `otherGames`/`onOpenGame` 透传给 Screen |
| 装配 | `BearHomeEntryProvider.kt` | ServiceLoader 发现，必须是普通 class（测试守门 public 无参构造器） |
| 界面 | `BearHomeScreen.kt` 等 | 房间状态机、Hub 热区、作息/天气页面渲染 |
| 纯逻辑 | `HomeRoutine.kt` | 时段表、日界、状态判定、时间文本 |

`BearGameOverlay`（app 层）负责口令触发：搜索框输入或外部激活信号 `(nonce, password)` 命中 `GameEntry` 后，同一时刻只激活一个游戏，并用 `key(activePassword)` 重建内容；`otherGames` 是装配方注入的其余已启用游戏（随 `-Pgames` 裁剪自动增减）。退出游戏时 `onExit` 清空 `activePassword` 并把天气页滚回第 0 页。

## 2. 作息时间轴

`HomeRoutineSlot(moment: SunPathBearMoment, startMinute, endMinute)` 是左闭右开的分钟区间；`HomeRoutineStatus` 只有 `DONE`/`NOW`/`SOON` 三态。边界全部复用 `:core:designsystem` 的 `BearRoutineTimes`，与天气页太阳弧共用同一套常量，避免两处各自维护魔法数字导致错位：

| 常量 | 值 | 含义 |
|------|----|------|
| `DAY_BOUNDARY_MINUTE` | 300（5:00） | 作息日界 |
| `MORNING_EXERCISE_END_MINUTE` | 390（6:30） | 晨练结束 |
| `MORNING_STROLL_END_MINUTE` | 435（7:15） | 晨间逛逛结束 |
| `BREAKFAST_END_MINUTE` | 495（8:15） | 工作日早餐结束 |
| `MORNING_OUT_END_MINUTE` | 540（9:00） | 通勤结束 |
| `WEEKEND_BREAKFAST_END_MINUTE` | 585（9:45） | 周末早午餐结束 |
| `LUNCH_START_MINUTE` / `LUNCH_END_MINUTE` | 690 / 750（11:30 / 12:30） | 午饭区间 |

`homeRoutineSlots(date)` 按 `isWeekend(date)` 返回两套连续时间表（工作日 16 段、周末 12 段）：

| 时段 | 工作日 | 周末 |
|------|--------|------|
| 05:00–06:30 | `ALMOST_DAWN` | `ALMOST_DAWN`（持续到 07:15） |
| 06:30–07:15 | `MORNING_EXERCISE` | `ALMOST_DAWN` |
| 07:15–08:15 | `MORNING_STROLL` | `WEEKEND_MORNING` |
| 08:15–09:00 | `BREAKFAST` | `WEEKEND_MORNING` |
| 09:00–09:45 | `MORNING_OUT` | `BREAKFAST` |
| 09:45–11:30 | `WORK_MORNING` | `WEEKEND_EXPLORE` |
| 11:30–12:30 | `LUNCH` | `LUNCH` |
| 12:30–15:00 | `WORK_AFTERNOON` | `WEEKEND_EXPLORE` |
| 15:00–15:45 | `AFTERNOON_TEA` | `WEEKEND_AFTERNOON` |
| 15:45–18:00 | `WORK_AFTERNOON` | `WEEKEND_AFTERNOON` |
| 18:00–18:45 | `HEAD_HOME` | `WEEKEND_RETURN` |
| 18:45–19:00 | `EVENING_EXERCISE` | `WEEKEND_RETURN` |
| 19:00–20:00 | `DINNER` | `DINNER` |
| 20:00–23:00 | `EVENING` | `EVENING` |
| 23:00–24:00 | `BEDTIME_PREP` | `BEDTIME_PREP` |
| 00:00–05:00 | `SLEEP` | `SLEEP` |

### 2.1 日界与状态判定

`homeRoutineDay(date, now)` 规定 `[00:00, 05:00)` 仍属于前一天的作息日，因此展示日期用 `date.minusDays(1)`，避免把新一天尚未开始的时段误判为已结束。`homeRoutineStatus(slot, now)` 把钟点映射到可比较的时间轴：`[00:00, 05:00)` 的分钟 `+24*60` 挪到轴末端；`SLEEP` 这类 `startMinute < 日界且 endMinute <= 日界` 的跨日段，`axisEnd` 取 `24*60 + DAY_BOUNDARY_MINUTE`，于是凌晨 0 点时入睡准备判 `DONE`、睡觉判 `NOW`（`routineStatus_afterMidnight_onlySleepIsNow`）。其余情况：`axisNow in [axisStart, axisEnd)` → `NOW`，`axisEnd <= axisNow` → `DONE`，否则 `SOON`。

时间表首尾相接、无重叠，因此任一时刻恰好一段 `NOW`；`routineStatus_bedtimePrepStartsAt23h`、`routineStatus_weekendRoutineCovered`、`weekdayRoutine_includesMorningStrollAfterExercise` 分别锁住 23:00 入夜、周末 9:00 早餐/9:45 旅行两段、工作日晨练接晨逛的边界。显示文本由 `formatHomeMinuteRange` 输出 `HH:mm–HH:mm`（`24:00` 特判），状态徽标由 `homeRoutineStatusLabel` 映射到资源。

### 2.2 UI 刷新策略

`BearHomeScreen` 用一个 60 秒的 `LaunchedEffect` 循环更新 `now`/`today`：

```kotlin
LaunchedEffect(Unit) {
    while (true) {
        delay(60_000)
        now = LocalTime.now()
        today = LocalDate.now()
    }
}
val routineDay = remember(today, now) { homeRoutineDay(today, now) }
val moment = remember(routineDay, now) {
    homeRoutineSlots(routineDay).firstOrNull { homeRoutineStatus(it, now) == HomeRoutineStatus.NOW }
        ?.moment ?: if (isWeekend(routineDay)) SunPathBearMoment.WEEKEND_MORNING
                   else SunPathBearMoment.MORNING_EXERCISE
}
```

Hub 展示的小熊插画 `bearResFor(today)` 与 `homeMomentNarrationRes(moment)` 都随 `moment` 重组；卧室列表用 `remember(routineDay)` 缓存 `slots`，每行再按当前 `time` 计算状态；小结的完成数与当前段同样按 `time` 派生。状态精度到分钟（忽略秒），加上 1 分钟轮询，跨段切换最坏有约 1 分钟延迟。

## 3. 房间与点位导航

房间由私有的九值枚举 `HomeRoom { HUB, LIVING, BEDROOM, KITCHEN, PLAYROOM, CLOSET, BALCONY, STREET, SUMMARY }` 表示，`room` 是唯一导航状态。

| 房间 | 内容 |
|------|------|
| `HUB` | 主插画 + 热区 + 底部旁白/小结入口，见下 |
| `LIVING` | 客厅：大图 + 当前旁白 + 「阳台/上街/小结」三个按钮 |
| `BEDROOM` | 卧室：全天作息列表，`NOW` 高亮，行 key 为 `"${moment.name}-${startMinute}"` |
| `KITCHEN` | 厨房：早/午/晚餐 tab + 五个菜系分组 + 菜品卡片（纯展示） |
| `PLAYROOM` | 游乐间：`otherGames` 入口列表，空列表显示提示 |
| `CLOSET` | 衣帽间：`rememberBearCharacterState()` + `GameCharacterPickerPanel`，角色设置独立持久化 |
| `BALCONY` | 阳台：天气插画/文案/粒子，详见 §4 |
| `STREET` | 街上：点位列表与点位详情，来源 `StreetSpot` 三个枚举 |
| `SUMMARY` | 今日小结：天气卡 + 作息时间线 + 完成计数 |

Hub 热区按 9:16 插画比例铺满：上层是卧室、客厅（含客厅上方的阳台窄条）、厨房，下层是游乐间、储物间；底部是口令提示、上街按钮与可点击的小熊/旁白区（进小结）。热区用 `HotZone` 统一实现，`clickable(onClickLabel = label)` 配 `semantics { contentDescription = label; role = Role.Button }`，标签只是低对比文本，主要靠语义树保证无障碍可读性。

导航动作：`openRoom`/`openStreet` 每次点击播放一次 `GameCue.UI_CLICK`；`openStreet(from)` 记录 `streetReturn` 作为街面返回目标；街上选中点位用 `streetSpot` 状态，进入详情页。返回键与顶栏返回的语义一致，仅 Hub/关闭按钮例外：

| 当前状态 | 返回键行为 |
|----------|------------|
| `HUB` | `onExit()` 退出小屋 |
| `STREET` 且 `streetSpot != null` | 清空点位，回到街面 |
| `STREET` | `room = streetReturn`（回阳台或客厅） |
| 其它房间 | `room = HUB` |

顶栏标题按 `room` 映射到资源，街上详情页显示点位名；`showBack = room != HUB`，关闭按钮始终 `onExit()`。厨房的 `slot`（默认早餐）、各页滚动位置等都属于一次进入的运行期状态；街上点位状态 `streetSpotStatusRes` 仅是白天/夜晚的静态文案映射，不代表真实营业时间。

## 4. 天气联动的阳台

### 4.1 天气映射与文案

阳台与小结共用一套 home 内映射：

- `isClearNight(sceneCode, isDay) = isDay == false && sceneCode in 0..1`：`:game:common` 的 `farmWeatherFromScene` 把夜间 0/1 归为多云，home 单独识别为晴夜以复用晴朗夜景插画；
- `homeDisplayWeather`：晴夜特判为 `SUNNY`，其余与 `farmWeatherFromScene` 一致；
- `homeWeatherLabelRes`：`sceneCode == null` → 「未知」；冻雨码（56/57/66/67，`isFreezingRainCode`）优先单独成类；雨天再按 `rainStrengthOf` 分小/中/大雨；晴夜显示「晴朗夜晚」。

`balconySceneArt(weather, isNight, date)` 选主图：晴天白天/夜间分开（夜间从 6 张 `BALCONY_CLEAR_NIGHT` 池轮换）、多云夜间从 4 张 `BALCONY_CLOUDY_NIGHT` 池轮换、雨天/雷暴/雾固定图、雪夜复用 `ic_sun_bear_evening_snowwindow`。轮换用 `dailyVariantIndex(date, salt, size)`（日期 + salt 哈希取模），同一天稳定、隔天变化；`balconyWeatherTip` 再按天气与昼夜给出旁白。

### 4.2 粒子与帧循环

阳台只在 `RAINY`/`STORMY`/`SNOWY` 有粒子，且 `reduceMotion` 为真时完全不注册帧循环：

```kotlin
val needsFx = weather == FarmWeather.RAINY ||
    weather == FarmWeather.STORMY || weather == FarmWeather.SNOWY
val reduceMotion = LocalReduceMotion.current
val fxActive = needsFx && !reduceMotion
if (fxActive) {
    GameFrameLoop(key = fxActive) { dt, _ -> timeState.floatValue += dt }
}
```

粒子绘制为纯 `Canvas`：`drawBalconyRain`（雨/雷暴 28/40 条，速度 900–1350 px/s，带横向摆动）、`drawBalconyLightning`（`sin(time*6) > 0.88` 时两段折线闪白）、`drawBalconySnow`（26 个圆点，横向用正弦飘移）。无特效时不注册 vsync，晴天/阴天/雾天长时间停留也不会空转唤醒主线程；`GameFrameLoop` 自带切后台停推与 dt 钳制。

## 5. 与口令枢纽、其它游戏的关系

`BearHomeEntry.Content` 把屏幕的 `onOpenGame` 收敛为「按口令切换」：`onOpenGame?.invoke(game.password)`。`BearGameOverlay` 在激活某个游戏时，把其余所有已启用 `GameEntry` 作为 `otherGames` 注入（用 `remember(activePassword, enabledEntries)` 过滤），游乐间因此随 `-Pgames` 裁剪自动增减，而游戏模块不需要反向依赖具体游戏。点击游乐间卡片会先播 `UI_CLICK`，再由 overlay 的 `launchGame` 切换 `activePassword`。

一个现行为值得留意：从游乐间进入子游戏后，子游戏的 `onExit` 会把 `activePassword` 置空并把天气页滚回第 0 页，**不会回到小熊的家 Hub**；想再进小屋需要重新输入口令。入口 provider 曾在 1.6.5 因误用 Kotlin `object` 导致 ServiceLoader 反射失败而崩溃，模块测试因此固定要求「普通 class + public 无参构造器 + `entry` 指向单例入口」。

## 7. 已知取舍与后续演进

| 取舍 | 现状与代价 |
|------|-----------|
| 无任何持久化 | 房间停留、街上点位、厨房选中餐段都是运行期 state，退出即丢；小屋也不提供存档 |
| 作息状态是时间口径 | `DONE` 表示「时段已过」而非玩家完成；没有打卡、好感度或事件进度系统 |
| 除衣帽间外为纯展示 | 厨房菜品、街上点位、阳台旁白、小结天气卡只读；没有「到点吃饭/到店买东西」的结算 |
| 分钟粒度 + 60 秒轮询 | 秒被忽略，跨段状态最坏约 1 分钟延迟；00:00/05:00 日界切换时最明显 |
| `isDay == null` 兜底白天 | Hub 主题与小结图标按白天处理，阳台标签走 `farmWeatherFromScene` 默认（晴天）；天气尚未加载的片刻可能与实况不符 |
| 子游戏退出回天气首页 | `BearGameOverlay.onExit` 清空激活口令并回到第 0 页，游乐间往返需要重新进小屋；不是缺陷但影响连贯性 |
| 街头状态是静态昼夜映射 | 便利店/茶馆/车站的文案只按昼夜切换，与作息时间轴、真实营业时间无关 |
| 导航只有一层记忆 | 没有历史栈与转场动画，仅 `streetReturn` 记住街面来处；深层路径不能原路返回 |
| 衣帽间独立持久化 | 角色设置由 `:game:common` 的角色状态管理，与 home 其它状态无耦合，也不算小屋进度 |

后续演进方向：把作息时间轴接到「到点触发」的轻事件（旁白/提示），让 DONE 具备行为含义；给游乐间增加返回 Hub 的路由选项；街头/厨房可考虑做可收集的图鉴进度；夜色与天气切换可加入低成本转场动画。

*本文档配套代码见 `game/home/src/main/java/com/xiaoxiong/weather/ui/game/`，测试见同模块 `src/test/java/.../ui/game/`。*

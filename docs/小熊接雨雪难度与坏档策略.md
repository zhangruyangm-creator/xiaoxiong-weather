# 小熊接雨雪：难度曲线与坏档策略技术说明

> 对应模块：`:game:catch`（小熊接雨雪）
> 核心文件：`BearCatchLogic.kt`（掉落物分布 / 加压曲线 / 世界推进纯逻辑）、`BearCatchGame.kt`（对局状态机、快照编解码、伤害结算）、`CatchRender.kt`（天空与天气氛围、物品/小熊/粒子绘制）、`CatchHud.kt`（HUD）、`BearCatchScreen.kt`（帧循环接线、输入、音效触感）、`CatchSkyPalette.kt`（天空配色与 HUD 暗角常量）
> 摘要：本文说明一款「接好物、躲危险」的竖屏接取游戏如何用天气决定掉落物种类、用难度档与分数双轴驱动加压曲线，如何用「危险占比硬上限 + 好物下限」保证可玩性，以及快照 20 字段与 19 字段旧档兼容、断连/无敌/护盾等容错语义和 HUD 暗角的对比度回归。

## 1. 分层与坐标系

| 层 | 核心文件 | 职责 |
|----|----------|------|
| 纯逻辑 | `BearCatchLogic.kt` | `ItemKind`/`CatchScene`/`CatchDifficulty` 枚举、掉落分布、加压曲线、`stepCatchWorld` 推进与接住/中招判定。无 Compose/Android 依赖 |
| 对局状态 | `BearCatchGame.kt` | 分数/心数/连击/护盾/双倍/死亡计时、伤害优先级、快照编解码、最高分与难度持久化 |

## 2. 难度档与加压曲线

### 2.1 `CatchDifficulty`

难度与天气解耦（皮肤/场景只保留底数差异），档位决定加压速率与危险加成：

| 档位 | `id` | 加压速率 `pressureRate` | 危险加成 `dangerBonus` | 爆发周期 s | 爆发速度倍率 |
|------|------|--------------------------|------------------------|------------|--------------|
| `CASUAL` | `"casual"` | 0.65 | 0.5 | 22 | 1.20 |
| `STANDARD` | `"standard"` | 1.0 | 1.0 | 18 | 1.30 |
| `CHALLENGE` | `"challenge"` | 1.45 | 1.5 | 15 | 1.40 |

`fromId(id)` 对未知/空值回退 `STANDARD`；标题界面选择后立即 `persistDifficulty` 写入 `catch_difficulty`，快照也保存档位（旧档缺省 STANDARD）。

### 2.2 t1 / t2 分段加压

`pressureOf(score, difficulty)` 把分数换算成两段进度：每 `PRESSURE_STEP_SCORE = 500` 分为一档，`progress = (score / 500) * pressureRate`，`t1 = min(progress, 1)`，`t2 = max(progress - 1, 0)`。`t1` 是首段（STANDARD 在 500 分封顶，CASUAL/CHALLENGE 按倍率推迟或提前），`t2` 是首段之后的继续加压量；`t2` 没有上界，因此分数继续涨、压力继续线性增大（测试覆盖到 3000 分仍增长）。

| 曲线 | 公式 | 下限/上限 |
|------|------|-----------|
| 生成间隔 | `spawnGapSeconds = base - 0.30*t1 - 0.05*t2` | 硬下限 `MIN_SPAWN_GAP_SEC = 0.18f` |
| 下落速度 | `fallSpeed = base * (1 + 0.9*t1 + 0.4*t2) * s` | 爆发波次再乘 `burstSpeedMultiplier` |
| 横风 | `windDrift = base * (1 + 0.6*t1 + 0.25*t2) * s` | 恒为正（向右） |

生成间隔的硬下限修正了旧版「500 分封顶且雷暴会低于注释下限」的问题；`spawnGapSeconds` 保证单调不增（`spawn gap shrinks monotonically with score`）。

### 2.3 各场景基础参数

`spawnBaseSeconds(scene)`、`fallSpeed` 与 `windDrift` 的场景底数（0 分 / STANDARD）：

| 场景 | 生成间隔底数 s | 下落底速 px/s | 横风底数 px/s | 分布特点 |
|------|----------------|---------------|---------------|----------|
| `SUNNY` | 0.68 | 390 | 0 | 花瓣 42% + 硬币 13%，晴天无横风 |
| `CLOUDY` | 0.68 | 390 | 0 | 雨滴 66% |
| `RAIN_LIGHT` | 0.60 | 440 | 60 | 雨滴 70% |
| `RAIN` | 0.56 | 490 | 90 | 雨滴 70% |
| `RAIN_HEAVY` | 0.48 | 570 | 130 | 雨滴 72%，硬币仅 4% |
| `SNOW` | 0.78 | 300 | 24 | 雪花 79%，慢而宽松 |
| `STORM` | 0.42 | 570 | 150 | 闪电 8% + 乌云 19%，有爆发波次 |
| `FREEZING_RAIN` | 0.60 | 440 | 60 | 冰雹 9% |
| `HAIL` | 0.44 | 580 | 120 | 冰雹 26%，有爆发波次 |

场景由 `catchSceneFromWeather(weather, sceneCode)` 映射：冻雨/冰雹码优先于普通雨/雷暴识别；雪 → `SNOW`；雨按 `RainStrength` 分三档；雷暴 → `STORM`；多云/雾 → `CLOUDY`；晴 → `SUNNY`。

## 3. 危险物进化与爆发波次

### 3.1 `itemKindFor` 按分数重分配

基础分布 `baseSlices(scene)` 是固定宽度的 roll 区间（0 分 / STANDARD 时与旧版完全一致）。分数抬高后：

```kotlin
val ramp = (score / DANGER_RAMP_SCORE).coerceIn(0f, 1f)
val extra = (DANGER_MAX_ADD * difficulty.dangerBonus * ramp)
    .coerceAtMost((MAX_DANGER_SHARE - baseDanger).coerceAtLeast(0f))
```

| 常量 | 值 | 语义 |
|------|----|------|
| `DANGER_RAMP_SCORE` | 1500 | 额外危险占比的爬坡分数上限 |
| `DANGER_MAX_ADD` | 0.12 | 满分时额外危险占比（STANDARD，按 `dangerBonus` 缩放） |
| `MAX_DANGER_SHARE` | 0.45 | 危险占比硬上限，保证好物 ≥55% |
| `HAIL_UNLOCK_SCORE` | 600 | 缺少冰雹的场景开始混入 HAIL |
| `LIGHTNING_UNLOCK_SCORE` | 1200 | 缺少闪电的场景开始混入 LIGHTNING |
| `NEW_HAIL_SHARE` | 0.45 | 新冰雹分走的额外危险占比 |
| `NEW_LIGHTNING_SHARE` | 0.30 | 新闪电分走的额外危险占比 |

`evolveSlices` 从好物区间按比例扣除 `extra`（`goodScale = (1 - baseDanger - extra) / (1 - baseDanger)`），既有危险按 `1 + baseGain/baseDanger` 放大，达到阈值后再把新危险挂到分布末尾。回归用例：`danger share rises with score while good stays majority`、`danger share is capped so good stays majority in dangerous scenes`、`high score mixes hail then lightning into calm scenes`。

### 3.2 爆发波次

| 常量 | 值 | 语义 |
|------|----|------|
| `BURST_WAVE_SEC` | 4.0 | 每个周期前 4 秒为波次 |
| `BURST_SPEEDUP_SCORE` | 1000 | 超过后周期缩短 |
| `BURST_SPEEDUP_SCALE` | 0.85 | 周期缩放（STANDARD 18s → 15.3s） |

`inBurstWave(time, score, difficulty)` 对 `time % period` 取正模后判断是否落在 `4s` 内。波次只在 `STORM`/`HAIL` 场景生效（`stepCatchWorld` 里 `burstWave = scene == STORM || scene == HAIL`），波次期间下落速度乘档位倍率，`FrameEvents.inBurstWave` 回传给 HUD 做闪烁提示。测试：`burst wave activates periodically in storm`。

## 4. 物品、容错与计分

### 4.1 物品表

| 物品 | 分值 | 伤害 | 半径 (×s) | 说明 |
|------|------|------|-----------|------|
| `RAINDROP` | 10 | 0 | 13 | 雨天主力 |
| `SNOWFLAKE` | 10 | 0 | 13 | 雪天主力（慢速、宽松） |
| `COIN` | 25 | 0 | 15 | 晴/多云稀疏高分 |
| `PETAL` | 8 | 0 | 13 | 晴天细小高频 |
| `GIFT` | 20 | 0 | 18 | 接住后双倍得分 `DOUBLE_TIME_SEC = 8s` |
| `BUBBLE` | 0 | 0 | 17 | 获得一次性护盾（`MAX_SHIELD = 1`） |
| `CLOUD` | 0 | 1 | 30 | 常见危险物 |
| `HAIL` | 0 | 1 | 16 | 快而致命 |
| `LIGHTNING` | 0 | 2 | 28 | 无视护盾直接扣血 |

`isGood` 把 `BUBBLE` 也算好物（可被接住、被风吹出屏不扣分）；`scoreOf(BUBBLE) = 0`，接住时不飘「+0」浮字。

### 4.2 连击、双倍与护盾

- **连击**：连续接住好物自增（GIFT/BUBBLE 也计入），漏接非 BUBBLE 好物清零；`comboScoreMultiplier(combo)` 在 `combo < 2` 时为 1，否则 `min(combo, 5)`，与 HUD 的 ×N 封顶一致；
- **双倍**：接住 GIFT 后 `doubleT = 8s`，期间所有得分（含 GIFT 自己）先乘 2 再乘连击倍率；再次吃礼物会重置换时长；
- **护盾**：`hasShield` 为一次性抵挡；被普通伤害消耗后进入 `SHIELD_COOLDOWN_SEC = 24s` 冷却，冷却结束前再吃 BUBBLE 不再叠加；闪电无视护盾；
- **受击无敌**：普通受击 `HIT_INVINCIBLE_SEC = 0.6s`；护盾格挡给 0.3s 无敌；无敌期间同帧所有命中忽略（物品已在引擎里移除）。

同帧多危险命中只结算一次，优先级 `hitPriority`：`LIGHTNING(0) > HAIL(1) > CLOUD(2)`，避免「4 块乌云同帧砸中吞伤」。测试：`multiple clouds same frame only deal one hit`、`lightning ignores shield and knocks two hearts directly`、`shield blocks hit and reports blocked instead of hit`、`bubble does not stack during shield cooldown`。

### 4.3 漏接语义与里程碑

- `stepCatchWorld` 把掉落物移出左右屏（`x < -r || x > width + r`）时**只移除**，不计 `missedGood`、不断连击——横风把物品吹出屏是玩家不可能接到的，与纵向漏接区分开（`items blown off left and right screen edges are removed without missed count`、`wind blown item does not break combo in game container`）；
- 纵向漏接（`y - r > height`）只有非 BUBBLE 好物计入 `missedGood`，`BearCatchGame.tick` 据此清零连击；
- 里程碑 `MILESTONES = [500, 1000, 2000]`，`milestoneFor(prev, new)` 返回本次跨过的最高值或 null，容器在加分时回调 `onMilestone` 飘一次大字；一次跨多个只报最高。

### 4.4 世界推进

`stepCatchWorld` 是纯函数入口（`stepCatchWorldDefault` 只是默认随机源包装）。每帧：

1. 生成：`spawnAccum += dt`，按当前 `spawnGapSeconds` 补生成，单帧最多 8 个、总数不超过 `MAX_ITEMS = 40`，初始 `vy = fallSpeed(..., burstActive, difficulty)`；
2. 移动：`y += vy*dt`、`x += wind*dt`；
3. 判定：圆心距离命中 → 分入 `caught` / `hit`；出左右屏移除；出底移除并按好物计数；
4. 返回 `FrameEvents(caught, hit, missedGood, spawnAccum, spawnedCount, inBurstWave)` 给容器消费。

## 5. 对局工程

### 5.1 快照：20 字段与旧档兼容

key `CATCH_SNAPSHOT_KEY = "catch_snapshot_v1"`，仅 `RUNNING` 可写；`OVER` 落盘时改为清档，`snapshotDiscarded` 置位后兜底保存也只清不写。

屏幕侧的进入恢复、`ON_STOP`/`onDispose` 兜底与退出抑制已统一由 `:game:common` 的 `GameSnapshotLifecycle`（`GameSnapshotSession.kt`）驱动；READY 与结算浮层已改用 `GameCards.kt` 的 `GameReadyCard`/`GameOverCard` 与 `gameBestLabel`/`gameViewRank`/`gameExit`/`gameRestart` 文案；`GameRenderPrimitives.kt` 提供 `BakedLayerLru`/`strokeOf`/`gameHash01` 渲染原语。

表头 20 字段（`CATCH_HEADER_FIELDS = 20`，旧版 19 字段 `CATCH_HEADER_FIELDS_LEGACY = 19`）：

| 下标 | 字段 | 下标 | 字段 |
|------|------|------|------|
| 0 | phase | 10 | inBurstWave |
| 1 | score | 11 | shakeT |
| 2 | hearts | 12 | squashT |
| 3 | combo | 13 | scene |
| 4 | doubleT | 14 | size.width |
| 5 | hasShield | 15 | size.height |
| 6 | shieldCooldownT | 16 | catchX |
| 7 | invincibleT | 17 | 触摸点占位 `-1f`（不恢复） |
| 8 | spawnAccum | 18 | best |
| 9 | time | 19 | difficulty |

其后每组成一个物品（首字段 `1`，7 字段）或粒子（首字段 `2`，11 字段，含 RGBA）。

**先解析校验后提交**：表头长度、`phase == RUNNING`、`hearts > 0`（合法对局不可能 0 心落盘）、`scene` 合法、物品 kind 合法、分组字段数足够，全部合法才写成员；`restoreSnapshot` 在解码失败、apply 抛异常、`applySnapshot` 返回 false 三种情况下都会清掉坏档并返回 false。旧 19 字段档没有 difficulty，`difficulty` 沿用当前值（通常来自 prefs，缺省 STANDARD）（`restore_legacyHeaderWithoutDifficulty_defaultsToStandard`）。

尺寸与生命周期的两个细节：

- `restoredDims` 记录存档尺寸：恢复后首次 `onSizeChanged` 若与存档一致，保留对局只重夹 `catchX`；暂停中改窗口用 `preserveRunning = true` 走同一路径，避免菜单分数与实际进度不一致（`resizeToSavedDims_keepsRunningGame`、`resizeWhilePaused_preservesRunningGame`）；真正旋转导致尺寸变化时置 `snapshotDiscarded` 并回 `READY` 重开；
- 触摸点不落盘、不恢复（避免小熊朝旧触点漂移）；`rng` 也不落盘，恢复后使用新随机序列，只影响后续生成。

### 5.2 最高分与排行榜

| 项 | key / 值 |
|----|----------|
| 当前最高分 | `PREFS_BEST_SCORE_KEY = "catch_best_score"` |
| 旧版最高分（迁移源） | `PREFS_BEST_SCORE_LEGACY_KEY = "best_catch"` |
| 难度 | `PREFS_DIFFICULTY_KEY = "catch_difficulty"` |

`loadBestScore` 在新 key 无值（`< 0`）而旧 key 有正分时迁移并回写新 key（`bestScore_migratesFromLegacyKeyAndRecords`）；`recordBestScore` 只刷新更高分，死亡回调里调用。排行榜 `leaderboard_catch` 只在 `score > 0` 时提交，清榜时同时清旧最高分 key，避免下次读取又迁移回来。

### 5.3 HUD 与死亡演出

`CatchHud.kt` 的 `CatchHud` 用 `derivedStateOf` 把每帧变化的浮点收敛成显示值，避免顶栏 60fps 重组：

```kotlin
val doubleSeconds by remember { derivedStateOf { if (game.doubleT > 0f) game.doubleT.toInt() + 1 else 0 } }
val shieldSeconds by remember { derivedStateOf { if (game.shieldCooldownT > 0f) game.shieldCooldownT.toInt() + 1 else 0 } }
val blink by remember { derivedStateOf { game.invincibleT > 0f && ((game.invincibleT * 10f) % 1f < 0.5f) } }
```

HUD 显示：双倍倒计时、连击 `×min(combo, 5)`、分数、心数（满/空）、护盾状态（持有/冷却倒计时/无）、爆发波次图标与最高分。

死亡流程：`hearts <= 0` → `hearts = 0`、`deadT = 0`、`phase = OVER`、回调 `onDeath(score)`；界面在 `onDeath` 里清快照、`recordBestScore`、提交排行榜，`LaunchedEffect(OVER)` 再补 `GameCue.LOSE` 并清档兜底。`deadT` 只在 `OVER` 阶段累加，`drawCatchBear` 用它算淡出 alpha（`1 - deadT*2`）；帧循环对整个 `OVER` 阶段乘共享 `gameOverTimeScale`（0.3）做慢动作，因此死亡演出与「整局 time 很大」无关（`death fade timer grows after game over and resets on restart`）。

### 5.4 音效与触感映射

| 事件 | 音效 | 触感 |
|------|------|------|
| 接住普通好物 | `GameCue.CATCH` | `CLOCK_TICK` |
| 接住 GIFT / BUBBLE | `GameCue.STAR` | `CLOCK_TICK` |
| 受击 | `GameCue.HIT` | `LONG_PRESS` |
| 护盾格挡 | `GameCue.BLOCK` | `CLOCK_TICK` |
| 里程碑 | 无 | `CLOCK_TICK` |
| 死亡 | `GameCue.LOSE`（`OVER` 时） | `LONG_PRESS` |

进入界面先 `GameAudio.preload(context)`；每帧最多播放一次「接住音」与一次「道具音」（`caughtSoundPlayed` / `powerUpSoundPlayed` 去重），避免同帧多件物品叠加爆音。

### 6.1 `CatchSkyPalette`

`CatchSkyStyle(top, bottom, hudScrimAlpha)` 提供懒加载的 `skyBrush`（顶/中/底三色，`skyGradient` 来自 `:game:common` 的 `GameSkyFx.kt`）与 `hudScrimBrush`（顶部黑色渐隐）：

| `catchSkySunnyNight` | `#1A237E` | `#3F51B5` | 0 |
| `catchSkyCloudy` | `#92A1AD` | `#CAD1D8` | 0.32 |
| `catchSkyRainLight` | `#7C94A8` | `#B4C7D2` | 0.26 |
| `catchSkyRain` | `#5D7B94` | `#9DB4C3` | 0.12 |
| `catchSkyRainHeavy` | `#47657F` | `#8198AC` | 0 |
| `catchSkySnow` | `#BEC7D3` | `#E8EDF2` | 0.45 |
| `catchSkyStorm` | `#33414F` | `#6B7B8A` | 0 |
| `catchSkyFreezingRain` | `#5A6E86` | `#A7BCC8` | 0.06 |
| `catchSkyHail` | `#3D5568` | `#8BA2B5` | 0 |

暗角参数：`CATCH_HUD_SCRIM_BAND = 0.42`（暗角覆盖屏高比例）、`CATCH_HUD_TEXT_BAND = 0.20`（HUD 文本区间）、`HUD_SCRIM_PLATEAU = 0.55`（全强度段占暗角层比例，保证文本区间不被渐隐削弱）。`CatchRender.kt` 的 `drawCatchHudScrim` 在天空/云/天气氛围之上、掉落物之下绘制，只压暗背景、不影响玩法元素。

### 6.2 对比度口径

浅色天空下白字直接压在天空上不足（晴天 `2.00:1`、雪天 `1.71:1`、多云 `2.65:1`），因此 `hudScrimAlpha` 按「HUD 文本区间内最亮的天空色」反推：叠黑 alpha 后纯白主文字需满足 WCAG 小号文本 AA `4.5:1`（留余量）。`CatchHudContrastTest` 遍历全部场景 × 昼/夜：alpha 必须落在 `0..0.6`，对比度 `>= 4.5`；`hudScrimPlateau_coversHudTextBand` 断言 `0.42 * 0.55 >= 0.20`，避免反推的 alpha 被顶部渐隐削弱。该测试同时是 `CatchSkyPalette` 的回归入口（调色板数值改动会直接反映在对比度断言里）。

### 6.3 氛围粒子与 `reduceMotion`

`CatchRender.kt` 的 `drawCatchWeatherBackdrop` 按场景画：小雨/中雨/大雨/雷暴用 `drawRainLayered`（层数 10/24/38/28）+ 风线，雷暴与冰雹叠 `drawStormLightning`，冰雹加 `drawHailPellets`，冻雨走 `drawFreezingRain`，雪画 18 个飘点。`reduceMotion` 为真时整个函数直接返回，只保留静态天空、云与地面——物理推进不受影响。

## 8. 已知取舍与后续演进

| 取舍 | 现状与代价 |
|------|-----------|
| 危险占比硬上限 45% | 保证好物始终 ≥55%，高分段危险不再线性增长；代价是 CHALLENGE 到后期只靠速度/间隔/爆发继续施压 |
| 好物口径包含 BUBBLE | `isGood` 把 0 分护盾算好物，危险占比统计因此宽松；好处是护盾不会被算成漏接 |
| 风恒为正（向右） | 风向不反转，玩家只需单向预判；代价是趣味性有限，风向变化留给后续演进 |
| 难度与天气解耦 | 天气只提供底数与风味，晴天也能按档位加压；代价是场景间的「体感难度」仍受底数影响 |
| t2 无上界 | 500 分后压力继续线性增长，生成间隔先触底 0.18s，下落/横风仍涨；极高分会越来越难直到死亡 |
| 横风吹出屏不计漏接 | 语义公平（玩家接不到），但物品无声消失需要风线视觉提示；代价是玩家可能以为「莫名少了一个」 |
| 坏档整档拒绝 | 0 心、场景/物品类型损坏直接清档，不尝试部分恢复；避免半个局面，代价是极端坏档丢进度 |
| 快照不存随机源 | 恢复后新 seed，后续掉落序列与存档前不同；保证实现简单 |
| HUD 与精灵闪烁频率不同 | HUD 用 `invincibleT * 10f`、精灵用 `* 12f`，两者相位不完全同步（纯视觉，无功能影响） |
| 飘字只显示基础分 | `+N` 用 `scoreOf` 原值，不含连击/双倍倍率；避免浮字与最终加分口径不一致的困惑，代价是数字偏保守 |

后续演进方向：风向可按场景/波次反转或增强；危险物可加入「诱饵」类（高价值但快速移动）；里程碑与爆发波次可以做成剧情化提示；`itemKindFor` 的分布表可外置成数据表以便调参而不改代码。

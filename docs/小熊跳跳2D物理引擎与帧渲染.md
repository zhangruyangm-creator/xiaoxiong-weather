# 小熊跳跳：2D 物理引擎与帧渲染技术说明

> 对应模块：`:game:jump`（小熊跳跳）
> 核心文件：`BearGame.kt`（`BearGame` 状态容器 + 快照/尺寸）、`BearGameScreen.kt`（帧循环接线/输入/结算卡）、`GameRunHud.kt`（`GameHud`）、`GameRunRender.kt`（`drawWorld` 等 Canvas 绘制）、`BearGameLogic.kt`（引擎层）；帧循环/暂停/快照/音效等复用 `:game:common`
> 摘要：本文说明一个跑酷小游戏如何用「纯 Kotlin + Compose Canvas」实现一套确定性、低 GC 的 2D 游戏引擎：显式欧拉积分、二段跳、由距离分数驱动的非线性速度曲线、dt 钳制游戏循环、无状态重组的 Canvas 渲染，以及「引擎层 / 表现层」分离后的可测性设计；并覆盖后续加入的土狼时间/跳跃缓冲、金币陷阱规避、连击里程碑、快照续玩与共享帧循环/音效层。

---

## 1. 背景与架构分层

小熊跳跳是一个单帧 Canvas 的跑酷游戏。物理与渲染全在 Compose 内实现，没有引入游戏框架。为了可测试，代码被刻意分成两层：

| 层 | 载体 | 职责 |
|----|------|------|
| **引擎层（纯逻辑）** | `BearGameLogic`（`object`） | 重力、跳跃初速、速度曲线、得分、步频、冰墙几何，以及核心物理推进 `stepBearPhysics`。**不含 Compose / Android 依赖**，可用普通 JUnit 测 |
| **表现层（状态+渲染）** | `BearGame` + `BearGameScreen` + `GameRunHud` + `GameRunRender` | 持有可变对局状态、世界实体（障碍/金币/云/粒子）、碰撞判定、粒子特效、快照/暂停接线；帧循环交给 `:game:common` 的 `GameFrameLoop`，HUD 在 `GameRunHud.GameHud`，Canvas 绘制在 `GameRunRender.drawWorld` |

引擎层通过**显式传入屏幕缩放 `s`** 而非读取 Compose `IntSize`，从而让同一套物理规则既能在 `BearGame` 里跑、也能脱离渲染被测。

**为什么值得写成文档**：这里隐藏着几个"看着简单、实则需要仔细权衡"的设计点——确定性物理怎么做、dt 怎么钳制、内存怎么不走 GC、以及"引擎与 UI 分离"如何在不改动随机序列的前提下完成。

## 2. 确定性物理：显式欧拉积分与二段跳

> 下面的量都乘以缩放因子 `s = size.height / 820f`，即按屏高归一，保证不同屏幕手感一致。

### 2.1 常量

| 物理量 | 公式 | 说明 |
|--------|------|------|
| 重力 | `g = 2500·s` | 垂直加速度常数 |
| 一段跳初速 | `jumpV = -960·s` | 触地时（`jumpsLeft == 2`） |
| 二段跳初速 | `jumpV2 = -830·s` | 已跳一次后（`jumpsLeft == 1`） |
| 极速 | `maxSpeed = 950·s` | 水平速度上界 |

### 2.2 显式（前向）欧拉

垂直推进用最简单的**显式欧拉**——先加速度再位移：

```kotlin
nvy = bearVY + g * dt
ny  = bearY  + nvy * dt
```

即一帧内 `v += g·dt; y += v·dt`。它不是最高精度的积分器（真实引擎会用半隐式欧拉或 Verlet），但**离散化方式确定、行为可预测**，且落地判定（见下）天然贴合这种顺序。文档要强调：**这里追求的是"确定性"而非"物理精度"**——只要 `dt`、`s`、初值确定，任何设备上的轨迹都逐帧一致[^1]，这正是可测性的基础。

[^1]: 前提是 `dt` 经过钳制（见 §4），真实设备帧率波动不会放大到破坏确定性。

### 2.3 落地判定与二段跳复位

`stepBearPhysics` 的落地逻辑：

```kotlin
if (ny >= floorY) {
    landed = !ngrounded      // 从空中→地面 视为「本帧落地」，触发挤压/扬尘
    ny = floorY              // 夹到地面
    nvy = 0f
    njumps = 2               // 重新给满两段跳
    ngrounded = true
} else {
    ngrounded = false
}
```

关键点：
- **`ny >= floorY`**：脚一旦越过地面就"贴地"，避免穿地/悬挂；
- **`njumps = 2` 复位**：触地即恢复二段跳次数，是最简单且手感明确的二段跳实现；
- **`landed` 与 `grounded` 分离**：`grounded` 是持续状态（决定能否跳）、`landed` 是**单帧事件**（由 `!ngrounded` 检测到从空中变地面），用于触发 `onLand()` 的挤压与踩地粒子——把"状态"和"事件"分开，是表现层副作用正确触发的关键。

`tap()` 现在先把点按解析成意图（`BearGameLogic.resolveJumpIntent`，见 §7.1）：`FIRST` 用 `jumpV`、`SECOND` 用 `jumpV2` 并触发空翻 `flipT`，两者都会清空 `airTime`/`jumpBufferT`；`NONE` 只写入跳跃缓冲等待落地消费。

## 3. 非线性速度曲线：由距离驱动的 Difficulty

跑酷游戏的难度推进方式有很多种。该项目刻意**不用"随时间线性加速"**，而用**纯距离分数驱动**的非线性曲线（`BearGameLogic.speedAt`）：

```kotlin
val p = (distanceScore / 5000f).coerceIn(0f, 1f)
return (340f + 610f * sqrt(p)) * s
```

- **开局 `340·s`**，约 `5000` 分时达极速 `950·s`；
- 用 `sqrt(p)` 而非 `p` 的用意：**前期增速快、后期增速放缓**——玩家刚上手时很快能感受到"越来越快"的刺激，而高手阶段速度趋于饱和、挑战转向"精确跳跃"而非"追速度"。
- 由于它是对**分数**（而非对时间）的函数，同一分数在不同设备上（`s` 不同）对应的手感一致——分数成了"难度"的横轴，天然跨设备统一。

得分 `score = (distance / (60·s)).toInt() + coinCount * 10`——距离换算成分数也除以 `s`，确保不同屏高得分可比。

### 3.1 步频封顶（防抽帧）

奔跑动画的相位速率也随速度走，但**封顶**（`runPhaseRate`）：

```kotlin
min(speed, 640f * s) * 0.031f / s
```

如果步频毫无上限地随速度增长，高速时的四肢摆动会在低刷率屏上表现为"抽帧/闪烁"。封顶 `640·s` 让步态频率在可渲染范围内稳定。

### 3.2 冰墙：随场景与分的"可跳性"设计

冰墙高度 `iceWallHeight` 取 `210·s`（冻雨）或 `195·s`（雪，更宽松），并注释了设计目标——**单跳够不到、二段跳稳过**。为验证这一点可以做个小估算：自由度初速 `960·s`、重力 `2500·s`，单跳最大抬升 `v²/2g = 960²/(2·2500) = 184·s`，二段跳叠加可达约 `322·s`。于是 `210·s` 恰好落在"单跳无法越过（>184）、二段跳轻松够到（<322）"的区间——**用物理常数反推门槛高度**，是数值设计自洽的好范例。

同时冰墙有**最低出现分数** `iceWallMinScore`（雪 300 / 冻雨 200）：低分段把本应生成的冰墙降级为雪人（`spawnType`），因为低分段玩家可能还没学会二段跳。这是"难度曲线"与"技能习得"的耦合设计。

## 4. 游戏循环：`GameFrameLoop` 与 dt 钳制

游戏循环已收口到 `:game:common` 的 `GameFrameLoop`（九款游戏共用），跳跳只提供 `onTick`：

```kotlin
GameFrameLoop(
    paused = { lb.show || showCharacterPicker || pause.paused },
    onTick = { dt, now ->
        val running = game.phase == GamePhase.RUNNING
        animDt += dt
        if (running || slowTick % 5 == 0) {
            val worldDt = animDt * gameOverTimeScale(game.phase)
            animDt = 0f
            game.tick(worldDt, ...)
            frame = now
        }
        if (!running) slowTick++
    },
)
```

四个刻意为之的细节：

1. **dt 钳制到 `0.033f`**：由共享层 `computeFrameDt(lastNanos, nowNanos, maxDtSeconds)` 完成——帧间隔过大时（切后台、卡顿、低端机掉帧）若用真实 dt，物体会"瞬移穿模"。钳到 33ms 上限，掉帧时世界推进变"慢动作"而非"瞬移"，碰撞不至于一帧穿透障碍。
2. **`lastNanos == Long.MIN_VALUE` 兜底 60fps**：首次进入或后台恢复时没有上一帧时间，直接用理想 60fps。
3. **非对局界面降频到约 12fps**：`running || slowTick % 5 == 0`——标题 / 结算界面没必要 60fps，每 5 帧才 tick 一次，**省电且减少无谓重组**；节流帧的 dt 按真实帧累计成 `animDt` 后整笔提交，避免动画以 1/5 速度运行；死亡演出再乘 `gameOverTimeScale(phase)`（`GAME_OVER_SLOW_MOTION_SCALE = 0.3f`）。`frame = now` 只在真正 tick 时写，Canvas 靠 `frame` 变量驱动重绘。
4. **后台/暂停自动停帧**：`GameFrameLoop` 在生命周期低于 `STARTED` 时 `delay(300)` 并重置帧时间——切后台/锁屏时 `withFrameNanos` 仍会派发，不暂停的话熊会继续跑并翻车；弹窗/暂停态（`lb.show`/角色选择/`GamePauseState.paused`）改为约 100ms 低频轮询，不注册 vsync，避免空转唤醒主线程。

`Canvas` 每帧重绘只靠读 `frame` 这个 `mutableLongStateOf`，`drawWorld` 里所有绘制都依赖 `game` 的普通字段——**只有分数/HUD 用 Compose state 驱动重组**，世界渲染不走快照重组，避免每帧创建新对象。

## 5. 碰撞与渲染的"手感"细节

### 5.1 判定盒内缩（宽容碰撞）

碰撞盒不是贴满整个熊，而是四周内缩：

```kotlin
val insetX = bearSize * 0.20f
val insetY = bearSize * 0.14f
```

内缩让"看着擦到但没真撞"的情况判为安全，**降低挫败感**——这是平台跳跃游戏惯用的"善意判定"（Fair Hitbox）。碰撞后 `die()` 触发死亡粒子、震屏 `shakeT`，并回调 `onDeath` 上报成绩。

### 5.2 金币收集用圆心距离

金币判定用**圆心距离 < 半径和**（`reach = c.r + bearSize * 0.52f`），比 AABB 更宽松，配合障碍上方的"金币弧"鼓励玩家按节奏跳跃（`coinArcYs` 生成 5 枚弧线）。收集时触发金币粒子 + `+10` 飘字 + 触觉反馈。

### 5.3 视差背景与 Path 缓存

背景云按 `layer` 分层（0.15 / 0.3）以不同速度左移（`x -= dx * layer`），形成视差。视差山丘的 `Path` 被缓存：

```kotlin
val hillPathCache = mutableMapOf<Pair<Float, Float>, Path>()
```

**key 是 `(heightRatio, s)`**——同比例同缩放复用同一个 `Path`，避免每帧重建 Path 引发 GC。结合 `PerformanceMonitor` 的 Debug 帧率埋点，可量化这些优化是否有效（见 `docs/性能监控与零开销设计.md`）。

### 5.4 场景驱动的粒子与障碍

游戏场景 `RunScene` 由**当前真实天气**映射而来（`runSceneFromWeather` —— 晴/阴/各档雨/雪/雷暴/冻雨/冰雹）。障碍生成概率也随场景变化（`obstacleTypeFor`，纯函数可单测）：雷暴天雷云占主导、雨天水坑为主、雪天雪人/冰墙为主。粒子系统（`burst`）在任意阶段都继续物理更新（`vy += 900·s·dt`）并 `iter.remove()` 回收死亡粒子。

## 6. 设计权衡小结

| 设计点 | 取舍 |
|--------|------|
| 显式欧拉 vs 高精度积分 | 换确定性、易测、落地判定自然；牺牲极端精度 |
| dt 钳制 33ms | 掉帧时"慢动作"而非"瞬移"，防穿模 |
| 速度曲线用 `sqrt(p)` | 前期刺激、后期趋饱和的难度手感 |
| 判定盒内缩 | 宽容碰撞降挫败感，牺牲"严格"判定 |
| 普通字段存世界状态、仅 HUD 用 state | 渲染零重组开销；代价是 HUD 与世界的更新通道分离 |
| 后台暂停 + 降频 | 防切后台翻车 + 非对局省电；代价是两次"非 60fps"的特殊分支 |
| 引擎/表现分离 + 传 `s` | 物理可单测、随机序列不变；代价是逻辑多了一层参数透传 |
| 土狼时间 0.09s + 跳跃缓冲 0.11s | 空中补跳/落地预输入更跟手；代价是点按意图多了两个时间窗 |
| 快照续玩 + 僵尸档清理 | 旋转/进程回收后续玩；代价是 22 字段 meta 校验与 `snapshotDiscarded` 状态机 |
| 帧循环/音效/雨雪收口 `:game:common` | 各游戏共享同一套 dt 钳制与事件音效；代价是行为改动需跨模块回归 |

**核心价值**：把"物理规则"和"画面状态"分开后，物理成为一组**纯函数**——`stepBearPhysics`、`speedAt`、`runPhaseRate` 等都能脱离渲染被 JUnit 直接验证，配合差分测试（parity test）可在重构时保证逐帧等价。这是小游戏里最值得复用的工程模式。

## 7. 后续演进：手感、陷阱规避与续玩

> 覆盖 1.13.0 当前实现；新增的纯逻辑都在 `BearGameLogic` 单测中命中。

### 7.1 土狼时间、跳跃缓冲与二段跳

| 常量 | 值 | 语义 |
|------|----|------|
| `COYOTE_TIME_SEC` | `0.09f` | 离地后仍可补第一段跳的宽限 |
| `JUMP_BUFFER_SEC` | `0.11f` | 落地前点按缓存，落地当帧消费 |

`resolveJumpIntent(grounded, airTime, jumpsLeft)`：`(grounded || airTime <= COYOTE_TIME_SEC) && jumpsLeft >= 2` → `FIRST`；`jumpsLeft == 1` → `SECOND`；否则 `NONE`。`tick` 里离地累加 `airTime`、触地清零；`grounded` 且 `jumpBufferT > 0` 时当帧转成起跳（`bearVY = jumpV; jumpsLeft = 1`）。测试：`BearGameJumpFeelTest.resolveJumpIntent_withinCoyoteTime_allowsFirstJump`、`tapBeforeLanding_isBufferedAndConsumedOnLanding`。

### 7.2 金币陷阱规避与障碍场景映射

冰墙高 195–210·s、需二段跳，旧写法把金币弧生成在墙体高度内，使"吃金币"变成"撞墙"；`coinArcYs` 现在对冰墙直接返回空数组，其余障碍按 `COIN_ARC_CHANCE = 0.4f` 生成 5 枚弧线（中心 `groundY - bearSize - (30 + lift*46)·s`）。`obstacleTypeFor(scene, r)` 按场景分段（r ∈ [0,1)）：

| 场景 | PUDDLE | SNOWMAN | ICE_WALL | STORM_CLOUD |
|------|--------|---------|----------|-------------|
| `SNOW` | `<0.14` | `<0.52` | `<0.76` | 其余 |
| `FREEZING_RAIN` | `<0.42` | `<0.60` | `<0.78` | 其余 |
| `STORM` / `HAIL` | `<0.30` | `<0.45` | 无 | 其余 |
| `RAIN*`（三档） | `<0.62` | `<0.80` | 无 | 其余 |
| `SUNNY` / `CLOUDY` | `<0.40` | `<0.72` | 无 | 其余 |

冰墙数值：`iceWallHeight = 195·s`（雪）/`210·s`（冻雨），`iceWallMinScore = 300`（雪）/`200`（冻雨）；`spawnType` 低于门槛时把冰墙降级为雪人。测试：`BearGameObstacleTest`、`coinArcYs_iceWall_neverSpawnsCoins`。

### 7.3 连击、里程碑与结算

吃币 `combo++`（HUD 在 `combo >= 2` 时显示），金币漏接（飞出左边界）或重开（`reset()`）即清零；分数跨过 500 的整数倍 `nextMilestone` 时飘字并递增阈值。死亡 → `die()` 置 `OVER` 并回调 `onDeath(score)`：播放 `GameCue.HIT`（`OVER` 再由 `LaunchedEffect(game.phase)` 补 `GameCue.LOSE`），最高分写 prefs `"best"`，正分向 `GameLeaderboardStore("leaderboard_run")` 提交 `LeaderboardEntry(score, timestamp, city, weather)`，名次存 `lb.lastRank` 展示。READY 与结算浮层已改用 `:game:common` 的 `GameCards.kt`（`GameReadyCard`/`GameOverCard` 与 `gameBestLabel`/`gameViewRank`/`gameExit`/`gameRestart`）。

### 7.4 快照续玩与尺寸变化

`JUMP_SNAPSHOT_KEY = "jump_snapshot_v1"`（`BearGame.kt`），meta 固定 `JUMP_SNAPSHOT_META_FIELDS = 22`（阶段/时间/距离/速度/金币/位置/跳跃态/动画与死亡计时/最高分/场景/宽高），后接障碍、金币、云三段列表；仅 `RUNNING` 可写可恢复。`ON_STOP` 与 `onDispose` 兜底落盘及退出抑制已统一由 `:game:common` 的 `GameSnapshotLifecycle`（`GameSnapshotSession.kt`）驱动；结束/重开/退出走 `clearSnapshot` 并置 `snapshotDiscarded`，抑制兜底回写（僵尸档清理）。`resize(newSize, preserveRunning)`：暂停中或尺寸与 `restoredSize` 一致时保留对局（距离按 `s` 折算，分数不变）；运行中真实旋转则回 `READY` 并清档；恢复先于首次 `onSizeChanged` 时用存档宽高兜底、`nextMilestone` 按当前分重算，避免重播里程碑。测试：`JumpSnapshotTest`。

### 7.5 音效、触感与减弱动画

| 事件 | 音效 | 触感 |
|------|------|------|
| 起跳/二段跳 | `GameCue.JUMP` | `KEYBOARD_TAP`（点按） |
| 吃金币（60ms 限流） | `GameCue.COIN` | `CLOCK_TICK` |
| 死亡 | `GameCue.HIT` + `LOSE` | `LONG_PRESS` |

`GameAudio.preload(context)` 在进入界面时预热。`LocalReduceMotion` 为真时 `drawWorld(reduceMotion = true)`，跳过雨雪/冻雨/冰雹/闪电粒子（`drawRunPrecip` 转调 `:game:common` 的 `GameWeatherFx`），只留静态天空与世界；浅色场景叠 `weatherSceneStyle(...).scrimAlpha` 的纯黑暗角，深色场景 `scrimAlpha = 0` 时整层跳过。
